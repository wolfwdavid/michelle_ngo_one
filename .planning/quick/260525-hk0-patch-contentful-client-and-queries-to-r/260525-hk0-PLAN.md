Exact replacement contents:

```ts
import { createClient, type ContentfulClientApi } from 'contentful';
import { CONTENTFUL_SPACE_ID, CONTENTFUL_ACCESS_TOKEN } from '$env/static/private';

/**
 * Minimal offline stub matching the subset of ContentfulClientApi that
 * `src/lib/contentful/queries.ts` consumes (only `getEntries`). Every query
 * function downstream resolves to safe defaults when `items` is empty, so this
 * lets the site render locally without Contentful credentials.
 *
 * Production builds (GitHub Actions sets both env vars) use the real SDK
 * client unchanged.
 */
function createOfflineStub(): Pick<ContentfulClientApi<undefined>, 'getEntries'> {
	console.warn(
		'[contentful] CONTENTFUL_SPACE_ID and/or CONTENTFUL_ACCESS_TOKEN missing — ' +
		'using offline stub. All Contentful queries will resolve to empty results.'
	);
	return {
		// Resolve to a shape compatible with `entries.items.map(...)` and
		// `entries.items[0]?.fields` in queries.ts.
		// eslint-disable-next-line @typescript-eslint/no-explicit-any
		getEntries: async () => ({ items: [] }) as any,
	};
}

const hasCredentials = Boolean(CONTENTFUL_SPACE_ID) && Boolean(CONTENTFUL_ACCESS_TOKEN);

export const contentfulClient = hasCredentials
	? createClient({
		space: CONTENTFUL_SPACE_ID,
		accessToken: CONTENTFUL_ACCESS_TOKEN,
	})
	: (createOfflineStub() as unknown as ContentfulClientApi<undefined>);
```

Key correctness rules — do NOT deviate:
- Guard MUST be `Boolean(SPACE_ID) && Boolean(ACCESS_TOKEN)` so an empty string also triggers the stub.
- When `hasCredentials` is true, the call to `createClient({ space, accessToken })` MUST be byte-identical to the current code so production behavior is unchanged. Do not add caching, retries, or default options.
- The stub MUST expose `getEntries` as an async function returning `{ items: [] }`. That single shape covers every consumer (verified across queries.ts — no other client method is called).
- Cast the stub via `as unknown as ContentfulClientApi<undefined>` so the public export type stays consistent and queries.ts compiles without changes.
- One `console.warn` at module init so the developer sees why content is empty. Do not log on every query.
- Do NOT add any environment files. `.env` is gitignored and `.env.example` already exists.
- Do NOT touch `svelte.config.js`, the GitHub Actions workflow, or any route/query file. The patch is one-file by design — every other layer already tolerates empty data.
